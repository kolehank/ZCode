## P0 —— 建议发布前决策

### 1. Windows broker 对任意本地进程无对端鉴权

- 位置：`packages/zcode-cua/helper/win32-x64/dist/windows-helper.js:14709`
- 证据：vendored 代码硬编码 `WINDOWS_PEER_IDENTITY_GATE_TEMPORARILY_OPEN = true`，代码自带的警告直言 "any local process can drive Computer Use"（`:25786-25791`）。Windows 生产路径（`runWindowsDevHelper`）从不传 `verifyPeer`（`:15549` peerVerdict 恒 null），连接对象初始即 `authenticated: true`（`:15559`），`assertPeerIdentityAuthCapable`（`:25704-25707`）也被该 gate 短路。
- 影响：任意本地进程连上 `\\.\pipe\zcode-cua-helper-*` 命名管道即可调用 `click` / `type_text` / `paste`（输入控制）和 `capture_app`（屏幕观察）；services 层的 `admitControllerAction` 控制器租约未接线（`packages/services/src/cua-permission-broker/` 全目录零命中）。
- 背景：上游（producer）的刻意临时决策（"Windows peer verification lands separately"），本批 vendor 把它带进了主仓产品。
- 建议：至少把 gate 翻转为 false 并保留 dev 显式 opt-in，或为管道设置 DACL；若接受现状，需要明确的产品确认记录。

## P1 —— 重要

### 2. web 远程访问 WS 升级无 Origin/Host 校验，open 档可被任意网页劫持

- 位置：`packages/desktop/src/main/webRemoteAccess/server.ts:219-265`、`packages/server/src/webAccessAuthBridge.ts:142-144`
- 证据：upgrade 处理只查路径和 token，无任何 Origin/Host 检查；`authorizeRequest` 的 default 分支直接 `ok: true`。
- 影响：open 档强制绑 127.0.0.1，但用户浏览器就在回环上——任意恶意网页可用 `new WebSocket("ws://127.0.0.1:…/ws")` 完成握手并桥到主窗口 Host，获得与桌面窗口等同的 RPC 权限（WebSocket 不受 CORS 约束，DNS rebinding 同样可行）。token 档因需要 token 而免疫。
- 建议：upgrade 时校验 `Origin`（仅放行 127.0.0.1/localhost 同源或配置内 externalBaseUrl）并校验 `Host` 头防 rebinding。

### 3. `stop()` 在有在线客户端时永不返回，设置页保存/停用被无限挂起

- 位置：`packages/desktop/src/main/webRemoteAccess/server.ts:278-283`、`controller.ts:129-133、147-152`
- 证据：`stop` 实现为 `wss.close(); server.close(() => resolveStop())`；活动连接存活期间回调不触发（ws 8.x + node 18 语义实测）。
- 影响：远端客户端在线时点"保存/停用"IPC 永不返回；磁盘配置已更新但监听仍按旧快照鉴权（新 token 迟迟不生效，停用后旧会话继续存活）。app 退出路径有 force-quit 兜底（`main/index.ts:821-828`），但正常收尾永不执行。
- 建议：stop 前先 `terminate()` 全部 clients 并调 `server.closeAllConnections()`；applyUpdate 的停-起加超时上限。

### 4. zcode-cua 防漂移门禁链整体失效

- 位置：`apps/zcode-cli/packages/zcode-cua-plugin/scripts/`（实跑验证）
- 证据：`check-cua-baseline.mjs` 实跑即崩（引用的 `upstream.json` 不存在，a53232e 后依赖改为 `workspace:*`、catalog git pin 已移除）；`check-version-coherence.mjs --check` 实跑 exit 1（运行时契约在 `helper/win32-x64/package.json:6-12` 子包，脚本读顶层 package.json）；两脚本共同引用的契约文档已删除；`bump-zcode-cua-producer.mjs:237-240` 自校验引用的 `tests/skill-sync.node-test.mjs` 不存在。脚本注释宣称的 "CI/pre-push 硬失败" 挂载点均已不存在。
- 影响：vendor 进来的 3.5 万行 `vendor/dist-index.js` 与 helper 载荷失去唯一防篡改/防漂移门禁，"看似有门禁"是假象。
- 建议：按 vendor 模式重写（CI 对 vendored 载荷跑 manifest 哈希校验，复用 `windowsCuaDevRuntime.ts` 的纯函数），或明确废弃并改掉注释。

## P2 —— 一般

### web 远程访问（5 项）

5. **CF 档 HTTP 鉴权分支是死代码**（`server.ts:171-207`）：`authorizeRequest` 对 cloudflare-access 恒 401，第二个异步验证块（`:189`）路径集合是第一块的子集、永远不可达。当前 desktop 不挂 /api 路由无实际放行后果，但后续加 API 会静默绕过 CF 校验。
6. **CF email allowlist 空串放行**（`saveRequest.ts:39`、`webAccessAuthBridge.ts:96-104`）：desktop IPC 的 `parseSaveRequest` 只 `trim` 不 `filter(Boolean)`；allowlist 混入空串时，无 email claim 的合法 JWT 命中空串候选被放行。server 形态 PUT 路由有过滤（`webAccessRoutes.ts:182`），desktop 路径没有。
7. **CF JWT 算法钉死 `["ES256"]`**（`webAccessAuthBridge.ts:91-95`，同 `webAccessMiddleware.ts:94`）：与 Cloudflare Access 现行 RS256 不一致，RS256 租户 fail-closed 全量 401，用户侧只有"CF 档连不上"一种表现。
8. **帧解码无缓冲上限**（`socketFrameBridge.ts:24-43`，依赖无上限 `ChunkStream`）：声明长度可达 4GB，客户端发送"永远凑不齐一帧"的字节即可让 main 进程内存无限增长直至 OOM。
9. **并发 `applyUpdate` 可把存活监听器孤儿化**（`controller.ts:129-133、154-184`）：`#handle` 在 `await` 之后赋值，两次并发保存叠加端口冲突时，存活 server 丢失唯一引用、永远无法 stop，`getStatus().running` 失真。

### zcode-cua（2 项）

10. **`reapOrphanedHelpers` 按进程名无差别 SIGTERM**（`broker-server.js:1535-1558`）：只匹配 "ZCode Computer Use" 字符串逐个杀，无 launcher 存活判定与路径校验。多窗口并发使用 CUA 时后启动进程会杀掉先启动窗口的活 Helper（darwin-only，对端 unexpected-exit 可自愈，但有一次可感知中断）。
11. **helper 载荷（含 404KB `ax_native.node`）与 manifest 同入 git、可同提交替换**：哈希校验只在 Windows 产品态运行时发生（`windowsCuaDevRuntime.ts:212-219`），CI 无校验。当前实测自洽（sha256 逐字节一致、五处版本均 0.6.3），属供应链纵深缺失。

### UI / byok（2 项）

12. **`maxOutputTokens` 无 map 兜底硬编码 `max_tokens` 字段名**（`packages/ui/src/settings/model-provider-section/ProviderModelMetadata.ts:283-290`）：对 openai-responses / openai-chat-completions 形态且未被内置 map 规则覆盖的模型（catch-all 规则只注入 max 无 map，命中即属此类），保存后 personal Overlay 物化为 `max_tokens`——正是该函数注释自述的事故场景。现有单测恰恰固化了"兜底 = max_tokens"行为。
13. **两处注释声称存在的 "defaultEnabled 机械对照单测" 不存在**（`packages/shared/src/plugin-marketplaces.ts:28`、`apps/zcode-cli/packages/bootstrap/src/app/official-plugin-definitions.ts:336`）：bootstrap test 目录只有 telemetry 测试。两份名单目前人工一致（各 10 项），但无漂移护栏。

### 构建/打包（1 项）

14. **SEA 官方插件清单 14 个版本号全部手工硬编码，无构建期校验**（`apps/zcode-cli/packages/cli/scripts/sea-official-plugin-assets.mjs:30-170`）：运行时按 name+version 精确匹配、不命中即静默跳过（`bundled-plugins.ts:270-276`），清单漏改时构建照样成功、用户侧静默缺插件。实测当前无漂移。
